# ML Churn Service

Сервис на Python и FastAPI предсказывает отток клиентов: `churn=1` — клиент
уйдёт, `churn=0` — останется. Поддерживает логистическую регрессию и случайный
лес, обучение через API, сохранение модели, пакетные предсказания и историю метрик.

## Запуск

Нужен Python 3.12. Из папки проекта:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn main:app --reload
```

Документация с примерами запросов: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs).
После первого запуска обучите модель через `POST /model/train`.
После последующих запусков сохранённая модель загружается автоматически.

## Датасет

В `data/churn_dataset.csv` находится искусственно сгенерированный набор:
2000 строк, 1597 клиентов с `churn=0` и 403 с `churn=1`.

| Поле | Тип | Значение |
|---|---|---|
| `monthly_fee` | float | Ежемесячная стоимость тарифа, неотрицательная |
| `usage_hours` | float | Часы использования за месяц, неотрицательные |
| `support_requests` | int | Число обращений в поддержку, от 0 |
| `account_age_months` | int | Возраст аккаунта в месяцах, от 0 |
| `failed_payments` | int | Число неудачных платежей, от 0 |
| `region` | str | `europe`, `asia`, `america`, `africa` |
| `device_type` | str | `mobile`, `desktop`, `tablet` |
| `payment_method` | str | `card`, `paypal`, `crypto` |
| `autopay_enabled` | int | Автосписание: 0 или 1 |
| `churn` | int | Целевая переменная: 0 или 1; нужна только для обучения |

В CSV обязательны все столбцы. Пустые значения признаков допустимы:
числовые заполняются медианами обучающей выборки, категориальные — значением
`missing`. Пустая целевая переменная недопустима. Для предсказания все девять
признаков обязательны; строки вместо чисел, булевы значения, неизвестные категории,
отрицательные и бесконечные числа отклоняются.

Разделение: 1600 строк для обучения, 400 для тестирования; стратификация по
`churn`, `random_state=42`. Числовая ветвь — `SimpleImputer` и `StandardScaler`,
категориальная — `SimpleImputer` и `OneHotEncoder`. `ColumnTransformer` объединяет
ветви, а `Pipeline` — преобразования и классификатор. Все преобразования обучаются
только на тренировочной части.

## Запросы

Обучить логистическую регрессию:

```bash
curl -X POST http://127.0.0.1:8000/model/train \
  -H 'Content-Type: application/json' \
  -d '{"model_type":"logreg","hyperparameters":{"C":1.0,"max_iter":1000}}'
```

Обучить случайный лес:

```bash
curl -X POST http://127.0.0.1:8000/model/train \
  -H 'Content-Type: application/json' \
  -d '{"model_type":"random_forest","hyperparameters":{"n_estimators":100,"max_depth":8}}'
```

Ответ содержит время, тип модели, использованные параметры и метрики на test:
`accuracy`, `f1`, `roc_auc`, `precision`, `recall`, матрицу ошибок.
`f1`, `precision` и `recall` относятся к уходящим клиентам, классу 1.
В матрице ошибок строки — истинные классы, столбцы — предсказанные, порядок `[0, 1]`.
Параметры по умолчанию включают `class_weight="balanced"` и `random_state=42`.
Доступные параметры и их ограничения видны в схемах `schemas/churn.py`.

Предсказание для одного клиента или списка клиентов:

```bash
curl -X POST http://127.0.0.1:8000/predict \
  -H 'Content-Type: application/json' --data-binary @examples/customer.json

curl -X POST http://127.0.0.1:8000/predict \
  -H 'Content-Type: application/json' --data-binary @examples/customers.json
```

Один объект возвращает `{"churn":1,"probabilities":{"0":0.25,"1":0.75}}`
(иллюстрация формата), список из 1–1000 объектов — список ответов в том же порядке.
Порядок полей входного JSON не влияет на предсказание.

| Маршрут | Назначение |
|---|---|
| `GET /` | Сообщение о запуске сервиса |
| `GET /health` | Доступность датасета и модели |
| `GET /dataset/preview?n=5` | Первые 1–100 строк |
| `GET /dataset/info` | Размер, столбцы, пропуски, распределение классов |
| `GET /dataset/split-info` | Размеры и распределения train/test |
| `GET /model/schema` | Признаки, типы и допустимые значения |
| `GET /model/status` | Текущая модель, время, параметры и метрики |
| `GET /model/metrics?limit=10` | Последние обучения, от новых к старым |

Историю можно отфильтровать: `/model/metrics?model_type=logreg`.
Модель, преобразования и история сохраняются одним файлом
`models/churn_model.joblib`. При неудачном обучении или сохранении предыдущая модель
остаётся доступной. Настройки путей: `CHURN_DATASET_PATH`, `CHURN_MODEL_PATH`.
Сервис рассчитан на один процесс Uvicorn.

## Ошибки

Все ошибки имеют формат `{"code":"...","message":"...","details":null}`.
Для ошибок полей `details` содержит их расположение и описание.

- `POST /predict` до обучения: HTTP 503, `MODEL_NOT_TRAINED`.
- `POST /predict` с пропущенным полем или `region="unknown"`: HTTP 422, `VALIDATION_ERROR`.
- `POST /model/train` с `{"hyperparameters":{"C":-1}}`: HTTP 422, `VALIDATION_ERROR`.
- Обучение без загруженного датасета: HTTP 400, `DATASET_NOT_LOADED`.
- Обучение с пустым датасетом: HTTP 400, `DATASET_EMPTY`.
- Повторный запуск обучения, пока оно идёт: HTTP 409, `TRAINING_IN_PROGRESS`.

`/health` отвечает HTTP 200, если процесс работает; `status="degraded"` означает,
что модель или датасет ещё недоступны. События загрузки, обучения, предсказания
и ошибок записываются в консоль.

## Docker

```bash
docker compose up --build -d
curl http://127.0.0.1:8000/health
```

API и `/docs` доступны на том же порту 8000. Том `churn-models` сохраняет модель
и историю после остановки или пересоздания контейнера. Внутри контейнера
приложение работает от отдельного пользователя.

```bash
docker compose logs -f
docker compose down
```

## Проверки и структура

```bash
pip install -r requirements-dev.txt
pytest -q
ruff check .
ruff format --check .
```

`api/` — маршруты, `schemas/` — схемы данных, `ml/` — загрузка данных, обучение
и сохранение, `core/` — настройки, состояние и ошибки, `main.py` — приложение.
Тесты проверяют подготовку данных, обе модели, сохранение и восстановление,
одиночные и пакетные запросы и ошибочные сценарии.

Примеры клиентов: `examples/customer.json`, `examples/customers.json`.
Результаты сравнения двух настроек на одной тестовой выборке:
`examples/training_comparison.json`.
Метрики ниже получены локально на macOS; версии Python и библиотек указаны в JSON.

| Модель | Accuracy | F1 для churn=1 | ROC AUC |
|---|---:|---:|---:|
| Логистическая регрессия, balanced | 0.5900 | 0.3543 | 0.6112 |
| Случайный лес, 100 деревьев, глубина 8, balanced | 0.6300 | 0.2816 | 0.6068 |

Постоянный ответ «останется» даёт accuracy 0.7975 и F1 0: он не обнаруживает
ни одного уходящего клиента. `class_weight="balanced"` увеличивает вес класса
оттока; у этих моделей есть ложные тревоги. Метрики относятся к указанной
тестовой выборке искусственных данных.
